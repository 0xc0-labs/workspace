# Discarded — do not propose

Part of the closed design ([the index](design.md)): not reopened without an
explicit decision from the operator.


| Discarded           | Reason                                               |
|---------------------|------------------------------------------------------|
| WireGuard           | Cloudflare Access + WARP already covers admin access |
| Coraza              | the OWASP CRS needs hand-tuning; CrowdSec's virtual patching does not |
| open-appsec, for now | every Kubernetes integration runs on retired or unmaintained pieces; can be reconsidered for the public applications (operator decision, 2026-09-29) |
| kube-vip, MetalLB    | the load balancer VMs keep the VIP for WARP and the API (operator decision, 2026-09-29) |
| BunkerWeb           | stores its configuration in SQLite                   |
| OPNsense, VyOS      | fragile network hop and immature providers           |
| SDN for the zones, with two nodes | EVPN, or a Simple zone per node: plain bridges over one Hetzner vSwitch per zone do the same with less. Put to the operator, he chose the simpler: «si vamos a ahcerlo asi mas sencillo, adelante, vamos co ello» (operator decision, 2026-11-23; infrastructure#271) |
| Terraform Stacks    | paid                                                 |
| OpenBao             | Vault's BSL does not affect this case                |
| SOPS+age            | replaced by Vault: every secret in one place, read over OIDC, nothing in the repos (operator decision, 2026-10-01) |
| Prometheus + Grafana, Loki, Tempo, until 2026-11-25 | **reversed on 2026-11-25**: they are the cluster's observability again ([platform](design/platform.md)). OpenObserve had replaced them as one light backend for the three signals, which suited one node with little memory (operator decision, 2026-10-01); with two nodes and servers of 16 GiB that no longer held, and the operator asked for the move: «ok pues seguramente cambiemos a ese stack, lo veremos después de lo que estamos ya» (operator decision, 2026-11-25; workspace#290) |
| VictoriaMetrics + VictoriaLogs | lighter than LGTM, but three backends to run where OpenObserve is one (operator decision, 2026-10-01) |
| OpenObserve | set aside on 2026-11-25 for Prometheus, Loki, Tempo and Grafana: its volume held millions of files (3.3 million when it moved), and containerd relabels a volume recursively when a container starts on a node that labels its containers, for longer than kubelet allows, so its start looped (workspace#288); and the move to the standard query languages and the community's dashboards (operator decision, 2026-11-25; workspace#290) |
| Alertmanager | Grafana Alerting instead: one place for rules, silences and destinations, with rules over Loki as well as Prometheus: «no se podría usar mejor grafana alerts? me gustan más» (operator decision, 2026-11-25; workspace#290) |
| An object store in the cluster, or Hetzner Object Storage, for Loki and Tempo | R2 holds their chunks and blocks, at cents a month with no egress fee. An object store in the cluster costs memory and a Longhorn volume and would be a third exception to the row on applications' files below; Hetzner's costs less only past about 400 GB, as its row says. A Longhorn volume is no way out either: Loki writes a file per chunk, which brings the relabel loop back (workspace#288) (the orchestrator's choice under the operator's delegation, 2026-11-25; workspace#290) |
| Alloy | the OpenTelemetry Collector stays the one entry point, `otel-gateway`: Alloy would have been there only to receive Faro, and the Collector has a Faro receiver upstream (the orchestrator's choice under the operator's delegation, 2026-11-25; workspace#290) |
| Two K8s clusters    | same hardware, adds no isolation; one cluster, separated by namespace (operator decision, 2026-09-24) |
| A VM per role (vm-edge, vm-apps, vm-data, vm-vault, vm-platform) | replaced by the cluster (operator decision, 2026-09-24) |
| Docker Compose on VMs | replaced by the cluster; `gitops` holds ArgoCD manifests |
| A QDevice | the second node takes 2 votes and the first 1 instead, so `pve-2` keeps quorum alone: «meteremos el nuevo nodo al cluster de proxmox y no añadiremos qdevice, luego a uno de ellos (ya elegirimos cual) le daremos voto de 2» (operator decision, 2026-11-23; workspace#285) |
| Egress per node | per-node egress only helps if something on `pve-1` must keep working while `pve-2` is down, and with `pve-2` holding every gateway, the SNAT, PBS and the 2 votes, and etcd and Vault unable to survive the loss of either node, nothing on `pve-1` does; it would cost two routes on every guest and an SNAT of its own on `pve-1`. Reconsidered if a service on `pve-1` must stay reachable, or reach out, while `pve-2` is down, such as a second WARP connector for break-glass access (operator decision, 2026-11-25: «ok si es mejor así»; workspace#285) |
| Three Longhorn replicas | every Longhorn node runs on `pve-2`: a disk failing is the RAID's, `pve-2` failing is PBS's, and an RKE2 VM failing is what two replicas cover; a third copy only covers two VMs failing at once, which is the host failing, where it does not help. Two give 50 % more room and a third fewer writes (operator decision, 2026-11-25: «si»; workspace#285) |
| Docker on the Proxmox hosts, for Traefik and RustFS | replaced by an LXC, `ct-base-01`, made by OpenTofu and configured by Ansible from `infrastructure`: «mejor lxc, puedes montarlo en el pve-2?» (operator decision, 2026-11-24; workspace#285) |
| Spreading etcd, Vault or the VM pairs across both nodes | with two nodes neither etcd nor Vault (3 members each, 2 needed) survives the loss of either one, so spreading them only changes which node is critical; the runners, the load balancers and the WARP connectors do nothing on `pve-1` without what `pve-2` holds: «vamos a dejar al principal que sea el tocho, movamos las VMs solo que sean necesarias al otro y listo» (operator decision, 2026-11-25; workspace#285) |
| A soft taint (`PreferNoSchedule`) on the application nodes | the scheduler only prefers to keep the infrastructure off them and gives up when it must, so the application nodes could not be sized for the applications alone; the hard taint keeps it off, and its cost is one maintenance window, once, as Longhorn's system components take a new toleration only with every volume detached: «pues creamos otro nodo de apps y hacemos taint fuerte y listo no?» and, told of the window, «sin problema, vale» (operator decision, 2026-11-25; workspace#288) |
| A PVC for the sandboxes | by Matchmark's design a sandbox is disposable, `emptyDir` only, deleted at the end of each attempt, and what survives is in Temporal, in Matchmark's RustFS and in git; the sandbox node has no Longhorn (operator decision, 2026-11-25; workspace#288) |
| Bug bounty lab      | reserved range, out of scope                         |
| Flux                | operator decision (2026-09-22): GitOps is ArgoCD     |
| One ordered pipeline for the cluster's deployment | the three steps stay apart: OpenTofu creates the VMs, Ansible configures them and installs ArgoCD, ArgoCD syncs gitops (operator decision, 2026-09-30, infrastructure#112) |
| A self-hosted registry (Zot, Distribution), for now | GHCR stores and serves container images free, private ones included; one in the cluster adds TLS, auth, a volume, a containerd mirror on every node, and an outage that stops every reschedule. Reconsidered if GitHub starts billing container storage (operator decision, 2026-10-10) |
| Mend's hosted Renovate | a third party with write access to the private repos, and the token that reads the private npm package kept at Mend, outside Vault; Renovate runs self-hosted from `.github` (operator decision, 2026-10-11; workspace#68) |
| A public CMS API | the frontends render on the server and read it inside the cluster; only the uploaded files are public (operator decision, 2026-10-11; workspace#68, for Payload). A site's Strapi is no different: its public role grants nothing, and its hostname serves the admin alone (operator decision, 2026-10-20; workspace#203) |
| Vault paths per application and environment (`apps/<app>/<env>/`) | the `apps` policy reads `apps/<namespace>/*` by the pod's namespace, and each environment is its own namespace (`<app>`, `<app>-staging`), so one policy covers every application and environment; a path per application and environment needs a policy per application (operator decision, 2026-10-11; workspace#87) |
| Amazon SES, for now | an AWS account, its sandbox, IAM and a bounce-handling circuit are not worth it with no volume; Resend over SMTP instead, so the move is credentials and DNS. Reconsidered when Mautic sends campaigns or the volume outgrows Resend's free plan (operator decision, 2026-10-12; workspace#92) |
| semantic-release | it releases on every push to a branch, the branch's last commit; a release here promotes the rc staging runs, an earlier commit if main moved on. git-cliff computes the version, one pinned binary where semantic-release is Node and plugins on runners that reach Vault (operator decision, 2026-10-11; workspace#87). An application with no staging does release every push, still with git-cliff, for the second reason: its release job runs on those runners (operator decision, 2026-10-12; workspace#140) |
| Longhorn RWX volumes for applications' files | an NFS share-manager is one more pod and one more single point, and the application still serves its files itself; R2 instead (operator decision, 2026-10-11; workspace#88) |
| Hetzner Object Storage, for now | a fixed monthly fee with 1 TB included, its own hostname with Cloudflare in front anyway, and another provider's keys, where R2 is free up to 10 GB with no egress fees. Reconsidered past about 400 GB, where it costs less (operator decision, 2026-10-11; workspace#88) |
| RustFS or an object store in the cluster, for applications' files | RustFS is run by hand on the node and holds the OpenTofu state; one in the cluster costs memory the cluster does not have to spare (operator decision, 2026-10-11; workspace#88). **Two exceptions: Plane's attachments**, in the object store its chart brings, for Plane alone: Plane signs every upload with a presigned POST, and R2 signs only GET, HEAD, PUT and DELETE; the cluster had about 22 GiB free when it was decided (operator decision, 2026-11-18; workspace#247); **and Matchmark's artifacts**, in a RustFS of its own, one server in its namespace with a 10Gi Longhorn volume, for Matchmark alone: its design asks for an object store, and the operator decided for it "for this application, for now", not R2 (operator decision, 2026-11-19; workspace#252, #253; gitops#429) |
| Manual Stripe tax rates for a tenant's checkout | a manual rate is one fixed rate whatever the customer's country; Stripe Tax applies each country's rate, the EU B2B reverse charge and the OSS reports, at a fee per transaction, and payload already supports it per tenant (`automaticTax` in Site settings → Subscriptions) (operator decision, 2026-10-17; payload#168) |
| A multi-tenant Payload as every web's backend | a client who buys a site cannot manage Payload's admin, while Strapi's is friendlier and can be branded; each site runs its own Strapi in its repo instead (operator decision, 2026-10-20; workspace#203) |
| gentle-ai as what leads the work inside an issue | replaced by `agent-skills`: it brings too much machinery of its own to each repo, a 526-line `.claude/CLAUDE.md`, nine agents, eight skills, a receipt-driven review with consent envelopes, Engram and two binaries pinned in `mise.toml`; it weighs too much in every session's context; and `agent-skills` is a standard pack, more active. `payload` kept it until workspace#204 retired that repo, on 2026-11-17 (operator decision, 2026-11-17; workspace#214) |
| `addyosmani/factory` | it does what the board, the autopilot and `work-issue` already do, by rules that are not the org's: branches named `claude/fq-N`, `factory:` commits, labels in place of the board's `Status`, PRs without `Closes`, and a log file per run (operator decision, 2026-11-17; workspace#214) |
